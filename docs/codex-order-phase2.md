# 発注書: 第 2 弾 — KanjiVG 自動生成で 151 字対応(1年生全部 + 2年生8月まで)

## 1. 目的・変更対象・スコープ外

- **目的**: 出題範囲を手作り 10 字から「1年生の全 80 字 + 2年生の 8 月までの 71 字 = 151 字」へ拡張する。漢字の形は KanjiVG(公開データ、ローカル同梱済み)から**ビルド時スクリプトで自動生成**し、設定画面で「学年 + 何月まで」を本当に選べるようにする
- **変更対象**: このリポジトリ全体。`docs/` と `vendor/` と `data/curriculum.json` は読むだけで変更しない
- **スコープ外**: 3〜6年生(UI は「じゅんびちゅう」のまま)/ 回転出題 / とめはねはらい地形 / 世界観テーマ / 村 / service worker。既存のゲームループ(探索 → 4択 → 種明かし)の構造は変えない

## 2. 制約

- 静的サイト + ビルド工程なしの構成は維持する。ただし**データ生成だけはビルド時の node スクリプト**(`tools/build-kanji-data.mjs`)で行い、生成物 `src/kanji-data.generated.js` をリポジトリにコミットする(実行時に SVG を読まない)
- ネットワークアクセス禁止。KanjiVG は `vendor/kanjivg-extract/kanji/<unicode下位5桁hex>.svg` に 6702 字分が展開済み(例: 木 = `06728.svg`)。zip・extract は .gitignore 済みなので生成物だけが git に乗る
- three.js は `vendor/three.module.js` 固定。npm パッケージ導入禁止(SVG パースも自前で書く。KanjiVG の path は M/C/S/c/s 等の SVG path 記法)
- UI 文言はひらがな多め・子ども向け。emoji 不使用
- 既存の照明強度(render3d.js の HemisphereLight 4.8 / DirectionalLight 3.6)は**下げない**。three.js r155+ の物理光量単位で調整済みの実測値(初版で「壁が背景と同色に沈んで全画面が無地に見える」不具合を実機で修正した経緯がある)

## 3. 関連 incident・同型事故

- 初版実装時、three.js r155+ の光量単位変更を考慮せず旧単位の感覚で照明を設定した結果、「描画は動くが暗すぎて何も見えない」状態になった(検収時に実機で発見・修正済み)。**見た目の明るさ・コントラストは静的検査で保証できない**。今回も色や光を触る場合は変更を最小限に
- スタート時にプレイヤーが壁へ正対していて画面が壁一色になる問題も検収で修正済み(`main.js` の initialYaw)。新しい 151 字でも「開始時に一画目の進行方向を向く」挙動を壊さないこと

## 4. 検収 oracle

- (a) `node tools/build-kanji-data.mjs` が成功し、`src/kanji-data.generated.js` に 151 字全てが入る(80 + 71 の検算をスクリプト内で行い、不足があれば非ゼロ終了)
- (b) `node test/maze-gen.test.mjs` 全通過。テストは以下に更新:
  - 151 字すべて: 迷路が単一連結 / スタートセルが通路上 / 通路セル数 > 0 / 通路セル比率がグリッド全体の 55% 未満(壁が消えて迷路でなくなる事故の検出)
  - 既知 10 字(一二三十口日田山川木)の橋本数が期待値と一致(一=0, 二=1, 三=2, 十=0, 口=0, 日=0, 田=0, 山=0, 川=2, 木=0)。KanjiVG 由来の座標で画同士がわずかに離れて偽の橋が出る場合は、近接端点のスナップ処理(1〜2 セル以内)を rasterize 側に入れて解決する(期待値の側を緩めない)
  - 出題プール抽出のロジック: (学年, 月) の全組み合わせで、含まれる字数が単調増加すること。(1年, 9月)=12字 / (1年, 3月)=80字 / (2年, 4月)=95字 / (2年, 8月)=151字 を厳密一致で検査
  - 得点テストは既存のまま維持
- (c) `python3 dev-server.py` で配信した index.html がエラーなくロードし、画数の多い字(曜・聞・線・頭)でも迷路が破綻しない(この項は発注側が Playwright + 実機で確認する)
- (d) README.md に KanjiVG のクレジット(CC BY-SA 3.0、http://kanjivg.tagaini.net へのリンク)を追記。ゲームの設定画面の下部にも小さく「かんじの かたち: KanjiVG」の一行を入れる

## 詳細仕様

### データの流れ

1. `data/curriculum.json`(作成済み・変更禁止)が正本: 学年ごとに `{month, unit, kanji[]}` の配列。1年は 9月〜3月、2年は 4月〜7月(8月は新出なし)
2. `tools/build-kanji-data.mjs` が curriculum.json の全 151 字について:
   - KanjiVG SVG を読み、**トップレベルの各 `<path>` を 1 画**として書き順どおりに取り出す(`kvg:` 属性の group 構造は無視してよい。path の d 属性のみ使う)
   - path をパースし、各画を折れ線(約 16〜28 点、曲率に応じて)にサンプリング
   - KanjiVG の viewBox (0 0 109 109) を 0..1 に正規化
   - 読み・意味は本スクリプト内の手書き辞書(下記)から結合
   - `src/kanji-data.generated.js` に `export const KANJI_DATA = [...]` として出力(各要素 = `{char, grade, month, unit, reading, meaning, strokes}`)
3. `src/kanji-data.js` は generated を re-export する薄い層にする(手作り 10 字の座標データは廃止してよい。ただし橋本数テストが通ることが廃止の条件)

### 読み・意味の辞書

- `tools/readings.mjs` に 151 字分を手書きする: `{ "一": {reading: "いち", meaning: "かずの 1"}, ... }`
- 読みはその学年の子が知っている代表的な読み 1 つ(訓読み優先、ひらがな表記)。意味は子ども向けの一言(10 字前後)
- 151 字に不足があればビルドが非ゼロ終了する検算を入れる

### 迷路グリッドの適応サイズ

- 画数でグリッドを変える: 1〜4画 = 31 / 5〜8画 = 39 / 9〜12画 = 47 / 13画以上 = 55(すべて奇数)
- `generateMaze(kanji)` が画数から自動で選ぶ。テスト・minimap・踏破率は maze.size を参照して動くように(31 固定の前提を除去)
- 画数が多い字は通路も長い。移動速度は変えず、`answer-button` はいつでも押せるので遊びは成立する

### 近接スナップ(重要)

- KanjiVG は視覚的に接している画でも座標がわずかに離れていることがある。rasterize 後、**別の画の通路セルから 2 セル以内にある画の端点セルは、その通路へ直結の 1 セル橋でつなぎ、type は "stroke" 扱い**(見た目の吊り橋にしない)。本当に離れたパーツ(川の縦棒同士など)だけが type "bridge" になるように距離しきい値を調整する
- 期待値: 上記 oracle (b) の既知 10 字で検証済みになること

### 設定画面

- 学年: 「1ねんせい」「2ねんせい」選択可。「3〜6ねん」はじゅんびちゅうのまま
- 月: 「いつまで」を学年に応じた選択肢にする(学校年度順):
  - 1ねんせい: 9がつ / 10がつ / 11がつ / 12がつ / 1がつ / 2がつ / 3がつ(ぜんぶ)
  - 2ねんせい: 4がつ / 5がつ / 6がつ / 7がつ(なつやすみまで)
  - 2年生を選んだ場合、1年生の 80 字は常に全部含まれる(累積)。UI にも「1ねんせいの かんじも でるよ」と一言添える
- 選択は localStorage(`kanji-maze-save-v1`)に保存し、次回起動時に復元する
- 4 択の誤答候補は「選んだ出題プール」から取る。プールが 4 字未満になることはない(最小 12 字)

### 正解画面の手直し(小)

- 種明かしの見下ろし(墨の軌跡)がカードに隠れて見えないので、結果カードを画面下部 1/3 のシート型に変え、上 2/3 で墨の漢字が見えるようにする(横画面では右 1/3 のカードでもよい)
- 得点内訳の「ふみはりつボーナス」は誤読(正しくは とうは)なので「たんけんボーナス」に改名

acceptance packet: 結論 / 変更ファイル一覧 / oracle (a)(b) の生出力 / 未解決事項・判断に迷った点(選択肢つき)。仕様への反証歓迎。
