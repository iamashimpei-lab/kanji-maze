## MVP 詳細仕様

### 画面の流れ

1. **設定画面（スタート画面）**
   - 学年: 「1ねんせい」のみ有効。2〜6 年はグレーアウトで「じゅんびちゅう」
   - 月: 「ぜんぶ」のみ（月別絞り込みは第 2 段階）
   - 地図: 「あり」/「なし（とくてんアップ）」
   - 北極星: 「あり」/「なし」
   - 「スタート」ボタン
2. **迷路画面（メイン）**
   - 3D 一人称視点で漢字迷路を歩く
   - 常設 UI: 「こたえる」ボタン、（地図ありなら）半紙風の地図、誤答回数と現在得点の目安
   - 「こたえる」→ 4 択パネル（正解 1 + 同じ出題プールから誤答 3、毎回シャッフル）。パネルは閉じて探索に戻れる
   - 誤答: ペナルティを表示して探索続行
3. **正解演出（最重要のご褒美。ここに一番手をかける）**
   - カメラが現在位置からなめらかに真上へ昇り、迷路全体の見下ろしに遷移（2〜3 秒のトゥイーン）
   - 自分が歩いた通路が墨の筆跡として浮かび上がる（未踏の通路は薄く）
   - 正しい向きの漢字を大きく表示 + 読み（ひらがな）+ 意味の一言
   - 得点の内訳（踏破率ボーナス / 誤答ペナルティ / 地図なし倍率）を表示
   - 「つぎのかんじ」ボタン → 出題プールから未出題をランダムに。プールを使い切ったらリセット

### 出題データ（手作りで同梱）

1 年生配当から次の 10 字: 一、二、三、十、口、日、田、山、川、木

各字のデータ形式（`src/kanji-data.js`）:

```js
{
  char: "十",
  grade: 1,
  reading: "じゅう",
  meaning: "かずの 10",
  strokes: [                     // 書き順どおりの配列。各画は正規化座標 (0..1, y は下向き) の折れ線
    [[0.1, 0.5], [0.9, 0.5]],   // 横棒
    [[0.5, 0.1], [0.5, 0.9]],   // 縦棒
  ],
}
```

- 座標は手作りしてよいが、**形がその漢字として認識できること**と、**接するべき画が rasterize 後に必ずセルを共有すること**（oracle の橋本数と一致）を自分で確認する
- 一画目の最初の点がスタート地点になるので、実際の書き始め（例: 横棒なら左端）に置く

### 迷路生成（`src/maze.js`、純ロジック・DOM 非依存でテスト可能に）

1. グリッドは 31×31 目安。正規化座標を余白つきでグリッドへスケール
2. 各画の折れ線を線分ごとに Bresenham で rasterize → 通路セル（画 id を記録）
3. 通路セルの連結成分を 4 近傍で求める。複数あれば、最も近いセル対を L 字経路でつないで橋セル（type: "bridge"）にする。単一連結になるまで繰り返す
4. スタートセル = 1 画目の折れ線の最初の点のセル
5. 踏破率 = 訪問済み通路セル数 ÷ 全通路セル数（橋セル含む）。訪問判定はプレイヤーがセルに入った時

### 得点（`src/score.js`、純ロジック）

- 基本点 = round(1000 × (1 − 踏破率)) + 200
- 誤答 1 回につき −300
- 地図「なし」設定なら合計を 1.5 倍
- 下限 0。端数は四捨五入

### 3D 表現（three.js）

- セル 2m、壁の高さ 2.5m、視点の高さ 1.5m。通路以外のセルは壁ブロックで埋める
- 橋セルは見た目を明確に変える: 床の色を変え、通路幅が細く見えるよう両側に低い柵や壁の張り出しを置く
- 夜の空（濃紺）。北極星 = 北の方角・仰角 35 度くらいに明るい光点 + 控えめな輝き。設定オフなら出さない。飾りの星を少々。MVP は迷路が常に正位置なので北 = 迷路の上
- 照明はシンプルに（環境光 + 方向光）。ポストプロセスなし。iPad で 60fps を目標に low-poly で
- 衝突はグリッドベースの単純判定でよい（壁セルに入れない）

### 操作

- **タッチ (iPad)**: 画面左半分 = 仮想スティックで移動、右半分 = ドラッグで視点回転
- **PC**: WASD + 矢印キーで移動、マウスドラッグで視点回転。ポインタロックは使わなくてよい
- 移動速度は子ども向けにゆっくりめ、視点回転も控えめの感度

### 地図（設定「あり」のとき）

- 画面隅に半紙風（生成り色）の小さな四角。訪問済みセルだけを墨色で塗る。自分の現在位置と向きを小さな印で表示
- 未訪問の通路・壁は描かない（描くと答えが見えてしまう）

### ファイル構成の目安

```
index.html
vendor/three.module.js   (同梱済み・変更しない)
src/main.js              (起動・画面遷移・ループ)
src/maze.js              (迷路生成・踏破率。純ロジック)
src/score.js             (得点。純ロジック)
src/kanji-data.js        (10 字のデータ)
src/render3d.js          (three.js の構築・描画)
src/controls.js          (タッチ + キーボード操作)
src/ui.js                (設定画面・4択・正解演出の DOM)
test/maze-gen.test.mjs   (oracle (a)。node 単体で実行可能に)
README.md
```

構成は多少変えてよいが、maze / score は DOM・three.js に依存させない（node でテストするため）。

### 納品形式

作業完了時に acceptance packet を出力する: 結論 / 変更ファイル一覧 / oracle (a) の実行結果（生出力） / 未解決事項・判断に迷った点。設計判断に迷ったら実装で勝手に確定せず、未解決事項に選択肢として書くこと。仕様自体への反証・現実との乖離の指摘も歓迎する。
